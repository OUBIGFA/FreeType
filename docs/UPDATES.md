# Windows 软件更新

自动更新默认关闭。用户可在「关于」中检查更新，或开启自动更新。开启后，FreeType 在每次启动时检查，运行期间的检查间隔为 24 小时。发现新版本后在后台下载，下次启动 FreeType 时安装；「立即更新」可直接下载并启动安装器。

## 更新来源与实现

更新只读取 `OUBIGFA/FreeType` 的 GitHub Releases。版本标签采用 `freetype-X.Y.Z`，附件采用 `FreeType-X.Y.Z-Setup.exe`，两者版本必须一致。草稿、预发布、其他标签和无对应 Windows 安装器的发布不参与更新。

版本选择、安装器下载、SHA-256 校验和下载文件的原子替换使用 [go-selfupdate v1.7.1](https://github.com/creativeprojects/go-selfupdate/tree/v1.7.1)。GitHub API 客户端与现有 `mygo/netproxy` 共用系统代理设置。FreeType 的适配层将 GitHub API 返回的附件 `digest` 交给更新库的 `SHAValidator`，所以公开 Release 仍只需一个 EXE 附件。

这采用常见输入法的「后台检查、下载完整安装器、重启后安装」流程。行为参考 [小狼毫的 WinSparkle 接口](https://github.com/rime/weasel/blob/master/include/winsparkle.h)。没有另外编写版本比较、下载器、校验器或可执行文件替换器。

GitHub 没有对应发布时，界面显示「尚无已发布的 Windows 更新安装器」。网络失败显示检查失败。上述情况均不显示「已是最新版本」。附件没有 SHA-256 或校验失败时，更新不能进入待安装状态。

## 安装与用户数据

- 自动更新开关保存在既有的 `%APPDATA%\FreeType\config.json`，随「全部设置」备份和恢复。
- 下载文件与待安装记录放在 `%APPDATA%\FreeType\updates`。它们属于安装缓存，不进入个人设置备份。
- 下载完成不修改当前应用或系统输入法。下次启动时，以及手动立即更新前，再用更新库核对下载文件。
- 更新运行现有 NSIS 完整安装器，安装目录保持不变。安装器负责停止同目录内的进程、复制程序、注册 x64/x86 输入法组件和恢复启动项。
- 系统输入法组件注册仍需要 Windows 管理员授权。注册失败时，安装器返回失败并保留待安装记录。同版本可重试未完成的注册；更旧的待安装器不能用于降级。
- 输入法组件注册成功后，安装器清除待安装记录，再启动 FreeType。
- 关闭自动更新会停止后续自动检查，并取消当前自动下载。已经下载的文件可通过「立即更新」手动安装。

## 验证范围

自动测试使用独立目录和本地 GitHub API 数据，调用真实更新库。测试覆盖正式版本选择、单 EXE 校验、后台下载、重启后读取、损坏缓存重新下载、默认关闭、重复操作、同版本未完成安装重试、旧版本拒绝，以及无发布和请求失败的区别。界面测试覆盖检查、立即更新、开关保存和搜索定位。

统一构建入口为 `windows/build.ps1`。固定测试安装器只在本地生成。发布真实新版本、操作已安装输入法或进行实际覆盖安装，需要对应任务的授权和验收；不以下载测试代替真实升级验收。
