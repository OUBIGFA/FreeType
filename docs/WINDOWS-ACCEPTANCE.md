# Windows 隔离安装与升级验收清单

**本文件是执行清单，不是验收报告。所有用例默认“未执行”。本次只准备清单，不安装、升级或卸载用户正在使用的 FreeType。**

适用范围：Windows 10/11 x64、固定安装标识 `io.github.oubigfa.freetype`、固定用户数据目录 `%APPDATA%\FreeType`。包含 x86 DLL 不代表支持纯 32 位 Windows。ARM64 不在本清单的支持承诺内。

自动测试只能证明已测逻辑。真实安装、UAC、系统 TSF 注册和应用内输入必须在获得单独授权的隔离测试机上完成。测试包通过也不代替正式版本安装包的验收。

## 1. 开始前准备

1. 使用可恢复快照的完整虚拟机或专用测试机。不得在用户的日常系统上运行本清单；仅换一个桌面或使用测试数据目录不足以隔离系统注册。
2. 关闭主机目录写入共享和自动共享剪贴板。只向测试机复制已核对的安装器、校验记录和人工测试数据，不复制真实词库、学习记录、密码或账号凭据。
3. 准备一个普通测试用户和一个独立的管理员测试账号。在系统 UAC 界面输入管理员凭据，不把凭据写入命令、日志或截图。
4. 保存干净快照 `S0`。确认测试机没有 FreeType 安装目录、用户数据、启动项或 TSF 注册。记录已有输入法，便于检查是否受影响。
5. 准备旧测试包 A 和新测试包 B。固定测试阶段二者都为 `0.0.1`，但内部构建号、源码树或组件 SHA-256 必须不同。每份包旁分别保存其原始 `build-info.json` 与 `.sha256`，不能共用一份记录，也不能重命名同一份包冒充升级。
6. 校验 A、B 的实际 SHA-256 与各自构建记录相符。记录数字签名状态；未签名测试包的摘要不等于发布者签名，不为绕过警告而全局关闭系统安全保护。
7. 在测试机准备 x64 Win32 编辑器、确认位数的 x86 编辑器、浏览器、商店应用和管理员权限编辑器。不要仅凭 `SysWOW64` 路径猜测程序位数；记录实际进程架构、应用版本和路径。
8. 为每个用例建立本地证据目录，记录 OS 完整版本、语言、用户类型、应用版本、包摘要、起始快照、操作时间、结果与证据路径。结果只用“通过 / 失败 / 未执行 / 不适用”；“不适用”须说明理由，不能用来跳过发布必测项。

Windows Sandbox 可辅助一次性首装，但不能单独覆盖多用户、持久数据、重启及 A→B 升级验证。发布声明包含的每种操作系统均需有完整结果。

## 2. 留证与统一失败处理

每个用例保存操作记录、界面截图或录像、安装器退出码（能取得时）、相关注册表查询、组件摘要及 `%LOCALAPPDATA%\FreeType\logs` 下的日志。只使用虚构输入；对外分享证据前再次检查个人路径和输入内容。

- **F0：停止依赖失败结果的后续用例。** 先留证，再恢复该用例指定快照。不要在同一个失败状态上反复试到成功后只记最后一次。
- **F1：允许用同一包重试。** 只用于用例明确安排的取消或失败恢复。保留首次失败与重试两套证据；重试成功不抹掉首次异常。
- **F2：停止发布。** 数据丢失、权限串用、错误成功提示、注册残留、误关其他程序、输入崩溃或无法恢复都视为阻塞。先修复，再从相同起点重跑受影响用例及其后续路径。

回滚使用虚拟机快照，或在已授权的专用测试机上恢复完整系统与数据备份。不要用手工删除注册表、改安装标识或换数据目录来“通过”用例。

## 3. 首次安装与注册

### I-01：干净首装并同意 UAC

- 状态：未执行。起点：`S0`。
- 操作：断开测试机网络，启动 B；选择默认安装位置，在 TSF 注册的 UAC 提示中同意管理员操作。
- 通过条件：安装完成；应用安装在当前用户的 `%LOCALAPPDATA%\Programs\FreeType`；默认词库、模型、声明和源码材料均在包内，不依赖联网补齐。托盘、服务、输入法列表和开机启动项各出现一次。
- 留证：完整安装过程、安装目录清单、进程路径、启动项、输入法列表、日志及组件摘要。离线时更新检查不可用不应破坏已安装输入功能。
- 失败处理：F0＋F2，恢复 `S0`。

### I-02：普通用户由另一管理员账号授权

- 状态：未执行。起点：`S0`，使用普通测试用户登录。
- 操作：由普通用户启动 B，在 UAC 界面使用管理员测试账号授权；回到普通用户桌面打开设置并输入中文。
- 通过条件：应用、启动项、输入法启用和 `%APPDATA%\FreeType` 都属于发起安装的普通用户。仅系统 DLL 复制及注册被提权；不把普通用户的数据写到管理员的配置目录，不以管理员身份常驻设置或服务。
- 留证：两个账号的用户配置位置、进程拥有者、注册查询和实际输入。记录测试用户 SID，但不记录凭据。
- 失败处理：F0＋F2，恢复 `S0`。

### I-03：取消 UAC 后重试

- 状态：未执行。起点：`S0`。
- 操作：启动 B，在注册 UAC 提示中取消；记录错误与退出状态。随后重新启动同一份 B，并同意 UAC。
- 通过条件：取消时明确报告未完成，不打开“安装成功”的应用、不把未完成状态冒充成功。应用文件可能已复制，不能把“取消”解释为完全无改动。重试后注册及输入恢复正常，没有重复启动项或输入法项。
- 留证：取消提示、取消后的目录与注册状态、重试过程和最终输入；能取得时记录取消路径的安装器退出码 `3`。
- 失败处理：F1；重试失败或出现假成功时 F2，恢复 `S0`。

### I-04：核对注册路径、版本和许可材料

- 状态：未执行。起点：I-01 或 I-02 成功。
- 操作：核对下面的只读查询；比较安装文件与 B 的组件摘要；打开总声明及若干许可、源码文件，并逐项校验 `third-party/manifest.json`。
- 通过条件：x64/x86 COM 注册分别指向相应 `Program Files\FreeType` 和 `Program Files (x86)\FreeType`；`ServerPath` 指向本次用户安装目录；应用、服务、两种 DLL 与安装器显示 FreeType 和相同产品版本。全部声明文件存在且摘要匹配，未解决授权项没有被隐藏。
- 留证：注册查询、五个文件的版本资源、安装后组件摘要和许可清单校验结果。只看文件名或 `0.0.1` 不能区分 A、B。
- 失败处理：F0＋F2，恢复相应用例的干净快照。

以下命令仅供已授权的测试机只读核查，不用于在主机注册或修复：

```powershell
$Clsid = '{6AEA9A65-33E4-4FFA-94E3-399C2ADC4CF1}'
reg query "HKLM\SOFTWARE\Classes\CLSID\$Clsid\InprocServer32" /reg:64
reg query "HKLM\SOFTWARE\Classes\CLSID\$Clsid\InprocServer32" /reg:32
reg query 'HKLM\SOFTWARE\FreeType' /v ServerPath /reg:64
reg query 'HKCU\Software\Microsoft\Windows\CurrentVersion\Run' /v FreeType
```

语言配置标识为 `{2C829DC6-FA03-477E-85D0-C64E1C64B209}`，语言 ID 为 `0804`。实现依据：`windows/protocol/src/lib.rs`、`windows/tsf/src/register.rs` 和 `windows/server/src/setup.rs`。

### I-05：x64/x86 及不同权限应用实际输入

- 状态：未执行。起点：安装与注册检查通过。
- 操作：在最低矩阵中的每个应用选择 FreeType，输入 `nihao` 并选“你好”；再检查整句、数字选词、翻页、Esc、回车、单按 Shift、中英文标点、切换输入框和原有快捷键。单独核对真实 x86 应用，不能以 x64 程序代替。
- 通过条件：组字、候选及上屏一致；候选窗跟随光标，不吞系统快捷键；密码框不接管输入；浏览器、商店应用和管理员应用均能正常输入。不同 DPI 下窗口不遮挡关键内容，其他输入法仍能使用。
- 留证：每个应用的版本、架构、权限级别、输入录像和日志。输入故障须关联具体应用，而不是只写“中文正常”。
- 失败处理：F0＋F2，恢复安装后的快照；保留崩溃或 TSF 错误证据。

### I-06：注销登录、重启和离线启动

- 状态：未执行。起点：I-01 至 I-05 相关路径通过。
- 操作：注销并重新登录测试用户，再重启测试机；保持断网，检查后台启动并再次输入。
- 通过条件：输入法仍启用，托盘和服务没有重复进程；不会每次开机弹出设置窗口；无需重新下载数据或重复授权。系统中的其他用户不意外共用此用户的词库或服务会话。
- 留证：启动项、进程归属、输入和日志。保存通过后的安装快照供后续用例使用。
- 失败处理：F0＋F2。

## 4. 同版本覆盖与失败恢复

### U-01：建立 A 的数据基线

- 状态：未执行。起点：`S0`，先安装 A 并确认可输入。
- 操作：设置不同的候选数量、Shift 行为和主题；导入一个虚构词库，增加快捷短语及多行常用语；产生可识别的学习词、选词次数、最近表情和状态栏位置。导出“全部设置”和“学习记录”，正常退出后备份用户目录，保存快照 `S1-A`。
- 通过条件：备份能解析，明确列出应保留的数据；自定义主词库也在备份范围。剪贴板、缓存和日志不作为必须保持内容完全相同的数据。
- 留证：A 的原始构建记录和摘要、导出文件、关键数据条目、用户目录清单。全部使用虚构内容，不向仓库提交这些文件。
- 失败处理：F0；不能建立有效基线时不得将后续升级用例标为通过。

### U-02：A→B 覆盖并保留全部用户数据

- 状态：未执行。起点：`S1-A`。
- 操作：不卸载 A，直接运行 B 并同意 UAC；首次输入前导出全部设置和学习记录，与 A 的基线比较；再核对组件摘要、词库功能、短语和输入。
- 通过条件：安装标识、安装位置和用户数据目录不变；B 的组件及新许可材料覆盖到位；设置、导入词库、自定义主词库、快捷短语、常用语和学习记录保留。没有重复输入法、启动项或卸载项。
- 留证：A、B 摘要、覆盖过程、升级前后导出比较和关键功能。比较实际条目与计数，不把日志时间、缓存变化误判为用户数据丢失。
- 失败处理：F0＋F2，恢复 `S1-A`，不要用空数据目录规避问题。

### U-03：正在使用 DLL 时覆盖

- 状态：未执行。起点：`S1-A`，保持一个 x64 与一个 x86 应用已加载 FreeType。
- 操作：保留未保存的虚构编辑内容，运行 B；先观察原应用，再关闭并重新打开这两个应用，检查新加载的 DLL 及输入。
- 通过条件：安装器不关闭或破坏这些编辑器及其内容。原进程可能继续使用旧 DLL，这是 Windows 的加载行为；重新打开后必须加载 B 的 DLL。旧文件可改名待重启删除，但不能把内存中的 A 冒充为 B。
- 留证：升级前后的应用 PID、架构、已加载模块路径、磁盘组件摘要、输入及临时旧文件。重启测试机后再核对待删除文件。
- 失败处理：F0＋F2，恢复 `S1-A`。

### U-04：覆盖时取消授权，再次安装恢复

- 状态：未执行。起点：`S1-A`。
- 操作：运行 B，在 UAC 取消；留证后重新运行同一 B 并授权。再次导出用户数据并测试输入。
- 通过条件：取消被报告为未完成，用户数据未清空；不宣称已自动回滚到 A，因为应用文件可能先于系统 DLL 被替换。重试后应用与系统 DLL 的摘要都属于 B，不留下新旧混装或重复登记。
- 留证：取消时的应用/系统 DLL 摘要和注册状态、错误提示、重试结果及数据比较。若由更新流程发起，失败时待更新记录应保留，成功后才清除。
- 失败处理：F1；重试失败、数据丢失或假成功时 F2，恢复 `S1-A`。

### U-05：准备步骤无法结束目标进程

- 状态：未执行。起点：`S1-A`；仅在测试机制造占用条件。
- 操作：使目标安装目录中的一个 FreeType 测试进程因权限无法被当前安装器结束，再运行 B；同时保留其他目录中的同名一次性测试进程。留证后解除条件并重试。
- 通过条件：准备失败时明确停止，应用文件尚未替换；其他目录的同名进程和同目录中的非 FreeType 程序不被结束。解除条件后能重试，学习记录可恢复。
- 留证：阻塞进程与对照进程的路径、拥有者、存活状态、错误提示、安装前后摘要；能取得时记录准备失败退出码 `2`。
- 失败处理：F1；误关对照程序、仍替换文件或数据损坏时 F2，恢复 `S1-A`。

### U-06：重复安装 B、正式版升级边界

- 状态：未执行。起点：A→B 成功后的快照。
- 操作：再次运行同一 B；之后检查重复项、数据和输入。正式发布时另从最后一个测试版快照运行已确认的正式安装包，重复 U-02 至 U-04。
- 通过条件：同包重装不破坏数据或重复注册。测试版→正式版路径必须使用真实正式构建及其摘要；固定 `0.0.1` 包改名不算正式版本升级。
- 留证：每次包记录、安装结果、用户数据比较和版本资源。当前尚无正式版本构建与授权时，将正式版子项保留为“未执行”，不能推定通过。
- 失败处理：F0＋F2，恢复升级前快照。

## 5. 卸载、重装与语言

### R-01：正常卸载并保留数据

- 状态：未执行。起点：B 安装、输入和数据检查通过。
- 操作：保存用户数据基线，从 Windows“已安装的应用”卸载 FreeType，同意注销 TSF 的 UAC；注销登录或重启后再次检查。
- 通过条件：应用、服务、启动项、输入法项和 COM 注册移除；其他输入法仍可用。`%APPDATA%\FreeType` 的设置、词库和学习数据保留。被占用而待删除的旧 DLL 在重启后清理，不以重启前的残留直接冒充已全部清除。
- 留证：卸载提示、退出状态、注册与文件查询、重启后状态、用户数据比较及其他输入法验证。
- 失败处理：F0＋F2，恢复卸载前快照。

### R-02：取消卸载 UAC

- 状态：未执行。起点：B 安装后的独立快照。
- 操作：从 Windows 发起卸载，在 TSF 注销 UAC 取消；检查提示、程序文件、启动项、TSF 注册和用户数据，再按已记录的恢复路径重试。
- 通过条件：不把注销失败报告为完整卸载成功，不留下“系统仍注册输入法但服务文件已删除”的不可用状态；数据保留，并有明确可执行的重试方式。
- 静态风险已修复并由自动回归覆盖：禁用失败返回 `5`；取消提权、注销失败或缺少本次成功标记时停止卸载，尝试重新启用当前用户输入法后返回 `6`；重新启用也失败时返回 `7` 并提示用安装器修复。只有本次注销成功才删除启动项和程序。自动测试使用一次性程序与独立注册表键，**本用例的真实 UAC 验收仍为未执行**。
- 补充核查：失败后原启动项、程序和用户数据仍在；取消后重新启动程序并实际输入，再重试卸载。注销已部分执行时，重新启用不保证系统组件全部恢复，应按提示运行安装器修复，不把返回码 `6` 当作完整回滚。
- 留证：UAC 取消、卸载结束提示、注册/文件不一致情况及重试过程。
- 失败处理：F2；留证后恢复快照，不手工抹去残留再登记“通过”。

### R-03：保留数据后的重装

- 状态：未执行。起点：R-01 成功，用户数据仍在。
- 操作：重新安装 B，同意 UAC；首次输入前导出设置与学习数据，之后检查词库、短语和输入。
- 通过条件：程序使用原 `%APPDATA%\FreeType`；原设置、词库、常用语、快捷短语及学习记录恢复可用；只有一个输入法和启动项。不要求恢复本来不持久化的剪贴板内容。
- 留证：重装前后数据比较、注册查询和输入结果。
- 失败处理：F0＋F2，恢复卸载前快照。

### R-04：三种显示语言和错误提示
