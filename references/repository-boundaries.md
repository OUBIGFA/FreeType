# 仓库边界与交付约定

2026-11-12 确认创建公开仓库 OUBIGFA/FreeType，默认分支 main。目标是 WowType 的 Windows 移植，前端采用 mygo。本阶段只准备仓库，不实现应用或安装器。

## 历史与远端

保留 WowType 提交 `1e047f7469f4e2f3da7a8a0cd49dbc8c0b46a0f1` 及其历史，不为清理当前树改写旧提交。

`upstream` 读取 WowType，本地禁用其推送地址；`origin` 指向 FreeType。只推送 `main`，不自动迁移上游其他分支、标签、Release 或通知服务。

WowType 基线没有子模块或 Git LFS 对象。当前仓库不启用符号链接或子模块；将来引入时另行核对来源、固定修订和 Windows 支持。

## 跟踪边界

| 内容 | 处理及原因 |
| --- | --- |
| 输入法源码、测试、锁文件、构建脚本 | 跟踪，保留行为对照和可复现输入 |
| ABI、移植、引擎、数据与使用文档 | 跟踪，与输入法实现直接相关 |
| 程序图标 | 逐文件登记后跟踪，属于应用资源 |
| 原始分析、旧报告、界面截图 | 从当前目录和索引移除，必要原理保留在技术文档中 |
| Telegram 机器人、通知脚本与工作流 | 移除，与输入法本体无关 |
| 上游发版工作流 | 移除，保留构建脚本；本阶段只启用仓库检查 CI |
| 本地项目工作约定与代理状态 | 忽略，不公开机器路径和本地操作授权 |
| 第三方来源、许可、二进制登记 | 跟踪，明确标记未完成的许可核对 |
| 缓存、工具链、私人数据、模型 | 不跟踪；需要时放 `.local/`，不预建空目录 |
| 安装器、校验文件、构建记录和日志 | 不跟踪，需要时放 `output/` |
| 一次性文件和测试仓库 | 不跟踪，只放 `_temp/<任务>/`，清理默认进入回收站 |

根 `docs/` 保留输入法技术文档，不照搬 Gitowl 的全部目录规则。已经移除的报告、截图和自动化仍列入忽略规则，防止误加回来。

`**/_temp/` 必须是根忽略文件最后一个有效规则。二进制只接受精确路径登记，需包含来源、许可证状态、字节数和 SHA-256；不能仅凭扩展名放行。

## 固定安装器与自动交付

代码任务完成后更新固定测试包，再提交并普通推送 `origin/main`。固定版本 `0.0.1`，安装标识 `io.github.oubigfa.freetype`，包路径 `output/release/FreeType-0.0.1-Setup.exe`。同时更新同名 `.sha256` 文件与 `output/release/build-info.json`。

构建记录必须识别实际源码树、内部构建号、工具链、依赖修订和包摘要。先生成包再提交时，不得把包错误标成另一个源码快照。用户数据目录在建立 Windows 应用时确定并保持稳定。

当前没有 Windows 应用，不生成空安装器；首个可运行版本建立时加入统一构建入口。之后构建或验收失败必须修复或报告，不交付旧包。

此约定不授权新分支、强制推送、标签、公开 Release、外部上传安装器或操作用户已安装的应用。

## 验证范围

统一入口为 `python -X utf8 tools/check_repo.py` 和 `python -X utf8 -m unittest discover -s tests/repository -v`。CI 使用完整历史核对上游归档摘要，不依赖开发机缓存。

登记变更需要重新核对来源和许可证；“已登记”不等于“许可审查通过”。仓库卫生也不证明 Windows 构建、功能、UI 或软件分发已通过。
